# EXPERIMENT_PROTOCOL — WWW 2027 revision (frozen 2026-10-09, before any recompute)

**This is a post-review revision protocol, NOT the original pre-submission preregistration.** Original frozen gates (HiGRC, FAR-Ground, prompt repair, proposal oracle, intervention) remain as recorded; nothing below retroactively edits them.

## R1. Revised parse policy (P0-4)
- Parser: `www2027_revision/src_rev/bbox_parser_v2.py` (D1 explicit-space precedence, D2 finite guard, D3 point-expansion flag). Same extraction cascade and dropped-decimal recovery rule as v1.
- Recovery remains protocol-determined per model config (InternVL norm1000 runs only), never GT-dependent.
- **Box-interface runs**: records whose parse lands in a point branch (json_point / point_recovered / molmo_point) are **parse-invalid** for the revised frames (no model-produced box). Counted and reported separately. Point-native interfaces (Molmo/Molmo2) keep point semantics in their own analyses only.
- All-attempt metrics: parse-invalid ⇒ IoU=0, localization failure. Valid-only metrics reported as diagnostics with explicit denominators.
- Applied uniformly to every model, method, and baseline; same parser for GRC/geometry/token/confidence features.

## R3. Revised joint-factor specification (P0-2)
- Primary: Binomial GLM (logit), y=1[IoU≥0.5] on parse-valid rows, terms: C(model_slug) + C(dataset_family) [dataset FE added] + expression_length_z + has_spatial + has_relation + has_attribute + likely_part + object_size_medium + object_size_small + target_edge + border_near + likely_part:object_size_medium + likely_part:object_size_small.
- task_naming / converted_annotation / style×family interactions are constant within dataset_family ⇒ **dropped from the dataset-FE primary** (not identifiable); style questions stay as the descriptive cross-setting comparison (existing Figure/rank analysis). No pseudo-inverse coefficient interpretation.
- Secondary direction check: Gaussian GLM on logit(clipped IoU), same RHS.
- Reported alongside: (a) pooled-adjusted legacy spec (old formula) for continuity; (b) model×dataset-cell FE robustness check; (c) leave-one-model and leave-one-family refits.
- Design diagnostics reported: matrix rank, reference levels, dropped/collinear columns.
- Part×size reporting: likely_part main = part effect at reference (large) size; conditional part effects at medium/small = sum with interaction; size terms conditional on part=0. Marginal contrasts, if plotted, standardized to the pooled parse-valid population.

## R4. Revised uncertainty & stability gate (P0-3)
- Primary inference: cluster-robust (canonical source-image) sandwich CIs from the GLM fit, plus a **source-image cluster multiplier bootstrap** (existing non-hierarchy path), 2,000 draws, seed 20261009.
- **Revised stability gate (frozen now):** a factor is "stable" iff (i) source-image cluster 95% CI excludes 0 in the primary dataset-FE spec; (ii) transformed-IoU secondary coefficient sign agrees; (iii) leave-one-model and leave-one-family sign agreement ≥ 0.8. The old product-sign model×dataset multiplier interval is retained only as a **named sensitivity** ("product-sign multiplier interval", with its no-cross-covariance limitation stated); it is no longer a pass gate. The number of stable categories is an outcome, not a target.
- GRC macro risk bootstrap: draw one multiset of canonical image groups per replicate from the union of group_ids, applied synchronously to all models/methods/coverages (paired). 2,000 draws, seed 20261009. 50%-coverage interval widening expected per the 500-draw diagnostic; point gains reported as-is.
- Rank-correlation resampling: resample canonical source-image groups shared across settings where linkable; otherwise report per-setting cluster CIs without pseudo-pairing of unrelated rows.
- Scope statement: all CIs quantify evaluation-sampling uncertainty for fixed OOF predictions over the evaluated model/dataset sets; retraining variation and generalization to future models/datasets are addressed only by LOM/LOF and held-out evaluations.

## R5. E1-A matched baselines (CPU, existing populations)
- Populations: (a) nine-model RefCOCO-family OOF (frozen nine_model_oof_index; 8,000×9, source-image-grouped 5-fold, verified no cross-fold leakage); (b) seven-model × five-setting multidataset OOF (existing per-setting GRC artifacts).
- Comparison rows (per model×population, identical folds, identical parse guard): random ordering; train-fold model/setting prior; raw verbal confidence (where exposed); confidence-only logistic; geometry-only logistic (= existing prob_success_geometry_only where already fitted with matched preprocessing — verified, else refit); simple area/edge/aspect rule (train-threshold); geometry-only GBDT (depth≤3, ≤200 trees, small frozen grid via nested inner folds) and full-feature GBDT (same grid, same budget); full GRC and existing minus-ablations; train-fold dataset/split prior; model×split-within AUROC to expose mixed-population inflation.
- Metrics: AUROC (failure positive), AUPRC (+prevalence), AURC, risk at 50/70/80/90% coverage. Paired full−geometry deltas with grouped bootstrap CIs (shared group draws, 2,000, seed 20261009). Losses/uncertain cells reported.
- Interpretation rule (frozen): if full−geometry ΔAUROC CI includes 0 in the same estimator class, the paper claims geometry-sufficiency, not full-feature necessity.

## R6. Stopping rules
- No re-drawing of test sets, seeds, thresholds, or metrics after seeing results; bootstrap draw count fixed at 2,000 (only raised for a specific pre-stated risk).
- Deterministic fits (logistic/GBDT) get no fake seed replication; label-budget curves use 5 fixed nested-subsample seeds (E4, separate protocol addendum when E3 data lands).
- Negative/unfavourable outcomes are reported, not re-run.

## R7. E3 Web grounding protocol (frozen 2026-10-09, before any model inference on Web data)
- Dataset: official Multimodal-Mind2Web (osunlp), splits train/test_website/test_domain, downloaded 2026-10-09 (12.3GB, split parquet shards; manifest in data/web/mind2web_raw). Split sizes verified = official (7,775/1,019/4,060).
- Target rectangle source: pos_candidates attributes.bounding_box_rect ("x,y,w,h", CSS px, 1:1 with the full-page screenshot). Alignment verified visually on rendered overlays (CLICK/TYPE/SELECT; united/booking/cargurus examples in outputs/mind2web_schema_check) — model-performed visual check, not a human annotation audit. Preference: is_original_target rect, else is_top_level_target.
- Task: grounding-only Web target localization, **oracle-action-conditioned** (description derived from target_action_reprs element role+label text; no coordinates, node ids, candidate sets, or future actions passed). Not an autonomous agent claim.
- Validity exclusions (model-independent, frozen, applied to every method and split): no_screenshot; no_pos_candidate; no rect; degenerate (w or h ≤1px); out_of_bounds; empty target text (<2 chars after stripping role); target center y>4096 (below_fold_4096). Excluded IDs + reasons recorded.
- Image input policy: top 1280×4096 crop of the full-page screenshot, no resizing at the task layer (model preprocessing untouched); predictions mapped back 1:1.
- Splits: fit=500 actions, calibration=200 actions, sampled label-blind from eligible train by whole annotation_id (task) groups, task-disjoint between fit/calib, seed 20261009; test = ALL eligible test_website actions; cross-domain boundary = ≤500 eligible test_domain actions sampled by whole tasks, stratified by domain, seed 20261009. Officially held-out website/domain relations preserved; no task/page crosses fit/calib/test.
- Models: Qwen3-VL-4B-Instruct + InternVL3.5-4B (already in project; one frozen prompt/interface each, chosen on calibration only). All reliability methods score the same frozen base outputs; token scores captured during generation (no extra calls).
- Primary outcome: center-of-predicted-box inside target rect (click-location proxy; overlapping elements/occlusion/action execution not verified). IoU≥0.5 secondary; IoU-vs-center 2x2 contingency reported by size/extent groups.
- Metrics/decisions per §8.3A: review fractions 10/20/30/50% (offline ranking) + calibration-frozen thresholds on test with task-cluster CIs; fallback (8.3B) only if calibration headroom justifies, main budget 25%.
- Inference counts: 2 models x (500+200+~860 test_website eligible+~500 domain) ≈ ~4,100 one-shot generations + frozen SafeGround-style K=10 subset per R8 (to be frozen before that run).

## R8. E4 natural-image label-budget curves (frozen 2026-10-09 before run)
- Per model (nine-model RefCOCO rebuild, frozen folds): test = frozen fold 0 (untouched); label pool = folds 1-4.
- Budgets B ∈ {50,100,200,500,1000,2000,4000} labeled rows, sampled as whole canonical-image groups (nested: larger budgets contain smaller), 5 fixed seeds (20261009+k). Budget counts actual labeled rows; unique images reported alongside.
- Heads per budget: geometry logistic, full logistic, geometry GBDT, full GBDT (GBDT grid frozen as R5; inner selection only within the budget's labels, grouped).
- Single-class budgets: score = prior; marked not-fittable.
- Metrics on fold-0 test: AUROC, risk@50% (train-side ranking); mean±range over seeds. No test-derived selection.

## R9. SafeGround-adapted sampling comparison (frozen 2026-10-09, before any sampling run)
- Scope decision rule (frozen): run K=10 stochastic sampling on ONE family (Qwen3-VL-4B, faster per smoke: 0.76s vs 1.31s/sample) over a frozen subset = 200 calibration actions + the first-500-by-manifest-order eligible test_website actions (= 700 inputs, 7,000 extra sampled generations, temp 1.0, same prompt/interface as base). - Score-only adaptation: spatial dispersion over the 10 sampled box centers (SafeGround-style density/margin measures adapted from points to box centers; weights 0.6/0.2/0.2 as in the paper), used as an uncertainty score for the FROZEN base prediction. No Clopper-Pearson threshold claim; no FDR guarantee claimed; labeled "score-only adaptation".
- Comparison: on the common 500-action subset, SafeGround-adapted score vs GRC heads vs geometry vs token under identical outcomes; full-population results reported separately for the single-call methods. Sampling cost (10 generations/decision + measured seconds) reported; infeasible at 25% extra-call budget -> shown on the cost frontier, not called cost-matched.
- Trigger: run only after base Web outputs land and calibration-side headroom check (oracle fallback headroom on calib >= 5 points) passes; else report A-only with the frontier note.

## R9.1. Amendment to R9: score-only sampling comparison (written 2026-10-16, before any sampled output exists)
Status: implementation and CPU tests complete; **GPU sampling NOT RUN** pending explicit author authorization of the budget in (10). R9 above is unchanged.

1. Reason. R9 tied the K=10 run to the calibration fallback-headroom trigger (>= 5 points). Measured headroom was 3.0%, so R9 was not run. That trigger concerns routing failures to a second model; it does not address whether sampling dispersion ranks failures of a fixed output better than single-pass scores. R9.1 removes the trigger for the score-only comparison only. Fallback routing/cascading stays closed by the R9 gate and is not part of R9.1.
2. Data exposure. Web labels, the base greedy outputs, all single-output scores and their results on test_website (including this 500-action prefix), and reviewer feedback have already been analysed. Only the sampled outputs and scores derived from them do not yet exist. R9.1 is a pre-specified comparison on fixed inputs, not a blind evaluation of an unseen test set.
3. Inputs. `r9_1/inputs_frozen.csv` (SHA-256 e33daf141a2025cfaf332ac58a6e445f41735d599b66b867e024751614668a9e): 200 calibration actions + the first 500 test_website actions in frozen record (= manifest) order. The prefix covers 83 tasks and 10 websites; one task is truncated (1 of its 5 actions). It is a fixed manifest-prefix sample, not random whole-task sampling. Base greedy outputs are reused (hash per input recorded), not regenerated.
4. Model and preprocessing. Qwen3-VL-4B-Instruct, Hugging Face revision ebb281ec70b05090aa6165b016eac8ec08e71b17 (local snapshot), bfloat16, transformers 4.57.6, torch 2.4.1+cu118, qwen-vl-utils 0.0.14; same chat template, `process_vision_info` + processor path and `norm_json_box` prompt as the base run. The resized frame the model sees (image_grid_thw x 16 px) is frozen per input and checked at run time.
5. Decoding. `do_sample=True, temperature=1.0, top_p=1.0, top_k=0, max_new_tokens=128`, `num_return_sequences=10` in one `generate` call per input after `torch.manual_seed(seed_i)`, `seed_i = 20261009 + position`. These values explicitly override the checkpoint's generation_config defaults (temperature 0.7, top_p 0.8, top_k 20); SafeGround states only temperature 1.0 and its repository contains no sampling code, so untruncated T=1.0 sampling is used. On CUDA out-of-memory only: two calls of 5 (seeds seed_i and seed_i+1,000,000), recorded as `sampling_mode`. Exactly 10 attempts per input; an unparseable sample stays unparseable (no redraw). Infrastructure failures (exceptions) get at most one retry in a separate pass; all attempts are logged and count toward the budget; inputs still failing are excluded from every method alike and counted.
6. Score. SafeGround-derived score-only adaptation, computed by the vendored, unmodified SafeGround code (`r9_1/third_party/SAFEGROUND`, commit 5e8fca7ef091bc6751cad9703ca430e775aa4433, MIT): points = centers of the parseable sampled boxes in the resized frame; U = 0.6*CD + 0.2*IE + 0.2*TA (code weight mapping checked against paper Eq. 5). Primary parameters = code defaults (patch 28, activation threshold 0.0); pre-specified secondary = paper values (patch 14, activation 0.3). Invalid samples are skipped (code behaviour); zero valid samples gives U = 1.0 (code). The frozen greedy box is ranked, never replaced; no output selection, Clopper-Pearson bound, FDR guarantee, or cascade.
7. Comparators (fixed now). Primary: the R3 token-only logistic head (510 fit labels). Secondary: raw coordinate-token entropy (0 labels), geometry+token logistic, geometry GBDT, full logistic (510 fit labels each). All are the existing per-row scores (`final_audit/per_row_scores_qwen3vl4b.parquet`) restricted to the same inputs. The sampling score uses no fit labels. All frozen thresholds use the 200 calibration labels.
8. Metrics and statistics. Outcome: click-location failure. Primary: Delta = AUROC(sampling, code defaults) - AUROC(token-only) on the 500 test inputs (average-rank ties). Paired task-cluster bootstrap over the 83 tasks: 2,000 draws, seed 20261009, one index set per draw for all methods, percentile 95% interval; draws with a single class are excluded and counted. Difference verdict: SAMPLING_BETTER if the lower bound > 0, SINGLE_OUTPUT_BETTER if the upper bound < 0, otherwise INCONCLUSIVE_DIFFERENCE. Non-inferiority: NOT_TESTED (no margin was justified in R9). Secondary: AURC, risk at 50% of the ranked test set, caught@20 (k = 100), AUROC differences against each other comparator; calibration-frozen threshold (accept iff failure score <= calibration median, the R3 rule) with realized test coverage and accepted risk, reported as a separate estimand. Per-website AUROCs are descriptive only and never used for selection. Scope of conclusions: this model, input panel, adaptation and metric; intervals reflect task sampling within these 10 websites. test_domain is not part of R9.1.
9. No result-driven changes: seed, score, parameters, inputs, K, and sample size are not changed after sampled outputs exist; negative and inconclusive results are reported in full.
10. Budget. New inference: 700 inputs x 10 = 7,000 sampled generations (700 generate calls). Full deployment cost of the sampling score: 1 greedy + 10 sampled generations per decision. Cap: <= 3.5 GPU-hours allocated on one A100 (partition a100) across the technical check and the main run; the runner stops cleanly at the cap; no automatic extension. Evidence for the estimate: the base greedy Web run on the same partition took 1.36 s/input (calibration) and 1.52 s/input (test_website); job 16302903 processed 3,066 inputs in 1:05:06 including model loading. Upper bound if batched sampling were no faster than 10 sequential calls: about 3.0 h; the batched call is expected to be faster (not measured).
11. Technical check before the main run (no accuracy criterion). Positions 0-9 (first 10 calibration inputs, 100 generations, counted in the budget and not regenerated). PROCEED only if: no run errors; image_grid_thw matches the freeze; at least one parseable sampled box; projected time for the remaining 690 inputs (+10% and 5 min) fits the remaining budget with a 10-minute margin. Otherwise STOP and report.
12. Execution note (2026-10-16, written after the main run and before any retry output exists). Technical check (job 16377843, 157 s) passed; main run (job 16378014, 3,265 s) completed all 700 inputs but 508 raised CUDA out-of-memory (both the 10-sample call and the 2x5 fallback). Error texts show a second process (PID 1214114) holding ~19.2 GiB of the 40 GiB A100 while our process held ~20 GiB; the failures are concentrated on tall screenshots (resized height >= 3008 px). This is an infrastructure failure, handled by the one-retry rule in (5): the 508 inputs are retried once with identical decoding, seeds, calls and fallback. Infrastructure-only changes for the retry: the job exits before loading the model if the GPU already holds > 1 GiB; before each input the runner stops cleanly (without attempting the input, so its single retry is not consumed) if other processes hold > 2.5 GiB; PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True. The 192 inputs that completed in the main run are kept as generated. Budget used so far 3,422 s of 12,600 s.

## R9.3. Reporting corrections (2026-10-17, after both runs; no rule, code, sample, or result changed)
1. The appendix caption of the full sampling table said "accept if the score is below its calibration median"; the rule frozen in R9.1 item 8 and implemented in `r9_evaluate.frozen_threshold` is "accept iff failure score <= calibration median". The caption now states the implemented rule and that ties at the median are accepted (Qwen code default: tau 0.26, calibration coverage 0.705; a strict "<" would give 0.415). A fixed tie-case regression test (`r9_1/tests/test_r9_threshold_ties.py`) pins the implemented rule.
2. "Untruncated samples" in the paper is replaced by the actual settings: top-k 0 and top-p 1.0 (no truncation of the sampling distribution) with output caps of 128 (Qwen) and 160 (InternVL) new tokens; 25 of Qwen's 7,000 samples reached the cap (all still contain a parsed first box) and are kept as generated.
3. Latency is reported as (base + extra K=10 call)/base over the same 700 inputs from the unrounded logs, with the infrastructure history of the Qwen run (182 of its 700 timings from the shared GPU); it is the latency of this implementation, not a controlled systems benchmark.
